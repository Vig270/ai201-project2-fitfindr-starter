### Tool 1: search_listings

**What it does:**
Searches the listings dataset for clothing items that match the user's description, size, and maximum budget. Returns matching listings sorted by relevance.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `description` (str): Keywords describing the clothing item the user wants.
- `size` (str): Desired clothing size
- `max_price` (float): Maximum price the user is willing to pay.

**What it returns:**
A list of matching listing dictionaries. Each dictionary contains:

- id
- title
- description
- category
- style_tags
- size
- condition
- price
- colors
- brand
- platform

**What happens if it fails or returns nothing:**
Returns an empty list. The agent informs the user that no matching listings were found and suggests changing the description, size, or budget. The workflow stops and does not call additional tools.
---

### Tool 2: suggest_outfit

**What it does:**
Generates an outfit recommendation using the selected listing and items from the user's wardrobe.

**Input parameters:**
<!-- List each parameter, its type, and what it represents -->
- `new_item` (dict): The clothing listing selected from search results.
- `wardrobe` (dict): The user's wardrobe containing an items list.

**What it returns:**
A string containing one or more outfit suggestions that combine the new item with wardrobe pieces.

**What happens if it fails or returns nothing:**
If the wardrobe is empty, returns a message explaining that outfit suggestions cannot be generated without wardrobe items. The agent informs the user and stops before creating a fit card.
---

### Tool 3: create_fit_card

**What it does:**
Creates a short social-media-style caption describing the selected item and outfit recommendation.

**Input parameters:**
- `outfit` (str): The outfit recommendation generated by suggest_outfit().
- `new_item` (dict): The selected clothing listing.

**What it returns:**
A short caption suitable for sharing on social media.

**What happens if it fails or returns nothing:**
Returns an error message indicating that outfit information is incomplete. The agent informs the user that a fit card could not be created.

## Planning Loop

**How does your agent decide which tool to call next?**
1. Receive the user's query and extract description, size, and max_price.
2. Call search_listings(description, size, max_price).
3. If the returned list is empty:
   - Store an error message in session state.
   - Return the error message to the user.
   - Stop the workflow.
4. Otherwise:
   - Store the first result as selected_item.
5. Call suggest_outfit(selected_item, wardrobe).
6. If no outfit suggestion is returned:
   - Store an error message in session state.
   - Return the error message to the user.
   - Stop the workflow.
7. Otherwise:
   - Store the outfit suggestion as outfit_suggestion.
8. Call create_fit_card(outfit_suggestion, selected_item).
9. Store the generated caption as fit_card.
10. Return the selected listing, outfit suggestion, and fit card to the user.

---

## State Management

**How does information from one tool get passed to the next?**
The agent maintains a session dictionary throughout the interaction.

Example:

state = {
    "selected_item": None,
    "outfit_suggestion": None,
    "fit_card": None,
    "error": None
}

After search_listings(), the selected listing is stored in selected_item.

After suggest_outfit(), the recommendation is stored in outfit_suggestion.

After create_fit_card(), the generated caption is stored in fit_card.

Each tool reads information from state that was produced by previous tools, allowing data to flow through the workflow without requiring the user to re-enter information.

## A Complete Interaction (Step by Step)

Write out what a full user interaction looks like from start to finish — tool call by tool call. Use a specific example query.

**Example user query:** "I'm looking for a vintage graphic tee under $30. I mostly wear baggy jeans and chunky sneakers. What's out there and how would I style it?"

FitFindr helps users discover secondhand clothing listings and build outfits around those items using pieces they already own. The agent first searches the listings dataset, then generates outfit suggestions using the user's wardrobe, and finally creates a shareable fit card. If no listings are found, the agent explains that no matches were found and suggests adjusting the search criteria rather than continuing to the next tool.

**Step 1:**
The agent extracts the user's search request and calls:

search_listings(
description="vintage graphic tee",
size="M",
max_price=30.0
)

The tool searches the listings dataset loaded through load_listings() and returns matching listings sorted by relevance. The best match is stored in session state.

**Step 2:**
The agent calls:

suggest_outfit(
new_item=selected_listing,
wardrobe=user_wardrobe
)

The selected listing from Step 1 and the user's wardrobe are passed into the tool. The tool analyzes wardrobe items and returns an outfit recommendation that complements the new item.

**Step 3:**
The agent calls:

create_fit_card(
outfit=outfit_suggestion,
new_item=selected_listing
)

The tool generates a short social-media-style caption describing the outfit and new purchase.

**Final output to user:**
Recommended Listing:
Faded Band Tee — $22

Outfit Suggestion:
Pair it with your baggy straight-leg jeans and chunky sneakers for a relaxed vintage streetwear look.

Fit Card:
"Found this faded band tee for $22 and it was basically made for my baggy denim"
